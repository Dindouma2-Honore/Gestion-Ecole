## 3. Matrice Type / Nature — source de vérité retenue

| Élément | Écrit par le chemin réel ? | Lu/affiché ? | Décision |
| :--- | :--- | :--- | :--- |
| `matieres.nature` (`in:matiere,domaine,activite`) | OUI — `MatiereResource::form()` + `CatalogueMatiereService::enregistrer()` (rule `required\|in:...`) | OUI — filtres `nature`, badges, sélecteurs | **SOURCE DE VÉRITÉ** |
| `matieres.type` (`matiere` \| `domaine_activite`) | NON — hors `$fillable`, jamais écrit par le formulaire ; écrit **uniquement** en clé non fillable par `MatiereService::creer()` (legacy) | NON — plus aucune colonne `type` dans `MatiereResource::table()` ; scopes `scopeMatieres`/`scopeDomaines` morts | COMPATIBILITY (conservé, non affiché) |
| Scope/vocabulaire `type` dans l'offre / affectation (`domaine_activite`) | voir P1.1 | hors périmètre P1.2 | Non traité |

**Résolution :** `nature` est la colonne métier. `type` reste pour compatibilité legacy.
Le service métier `MatiereService::creer()` écrit **désormais les deux** (via `naturePourType()`),
ce qui aligne la création par service sur la création par Filament **sans fusionner ni supprimer de colonne**.
Mapping explicite et documenté dans `MatiereService::naturePourType()` :
`TYPE_DOMAINE_ACTIVITE ('domaine_activite') → 'domaine'`, sinon `TYPE_MATIERE ('matiere') → 'matiere'`.
`activite` n'a pas d'équivalent legacy → non produit par ce mapping (pas d'invention).

## 5. `MatiereService::creer()` — persistance du discriminant

`app/Modules/Pedagogie/Services/MatiereService.php`

- Avant : `Matiere::create([...'type' => $type...])` → colonne `nature` **jamais renseignée**.
- Après : construction explicite avec `'nature' => self::naturePourType($type)`,
  puis `$matiere->type = $type; $matiere->save();` (affectation directe, hors `$fillable`,

- Le paramètre `$coefficient` continue d'hydrater **`coefficient` et `coefficient_defaut`** (inchangé).
