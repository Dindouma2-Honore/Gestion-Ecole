## 5. Types d'affectations
| Type | Cycle concerné | Stockage | Service | Usage production |
| :--- | :--- | :--- | :--- | :--- |

| `assistant` | Maternelle / Primaire (mode classe) | `affectations_pedagogiques` (`type = 'assistant'`) + `affectation_pedagogique_matieres` | `AffectationPedagogiqueService` | Actif |

- **Principe respecté :** POSTE RH (`Enseignant` / `Employe`) ≠ RESPONSABILITÉ PÉDAGOGIQUE (`AffectationPedagogique`). Un enseignant possède un statut RH et peut exercer plusieurs responsabilités pédagogiques.

## 6. Maternelle / Primaire / Secondaire
- **Maternelle / Primaire :** Mode `classe` configuré via `OrganisationCycle`. Un enseignant principal unique par classe, assistants généralistes ou spécialisés.
- **Secondaire (Collège / Lycée) :** Mode `matiere` configuré via `OrganisationCycle`. Enseignement par matière avec offre pédagogique obligatoire.
- **Classification :** **CONFIGURÉ** (via `OrganisationCycle` et `OrganisationPedagogiqueContext::modeClasse()`).

## 7. Affectation → Offre Pédagogique
- **OFFRE OBLIGATOIRE POUR TOUTE AFFECTATION :** **PARTIEL**
  - *Type `matiere` (secondaire) :* **OUI** (obligatoire, validé via `OffrePedagogiqueService::effective()`).
  - *Type `principal` / `assistant` (maternelle/primaire) :* **NON** (`offre_pedagogique_id` est `NULL` car ces rôles couvrent la classe entière et non une matière spécifique).

## 8. AffectationPedagogiqueService
- `enregistrer()` : Valide les données (`annee_scolaire_id`, `classe_id`, `enseignant_id`, `type`, `matiere_id`, dates, actif), vérifie le mode du cycle, contrôle l'existence et l'activité de l'enseignant et de la classe, vérifie l'offre effective (pour les matières), empêche les doublons et les conflits d'enseignant principal unique, gère les dates par défaut, utilise une transaction avec `lockForUpdate`, synchronise les matières spécialisées, et enregistre l'audit.
- `estAutorise()` : Vérifie si un enseignant est autorisé pour une matière, une classe, une année et une date données en recoupant son statut actif, l'offre effective et l'affectation active (principal, matière correspondante, ou assistant généraliste/spécialisé).

## 10. Sync classes.professeur_principal_id
- La colonne `classes.professeur_principal_id` existe dans la table Scolarité `classes`.
- Elle est écrite uniquement par le service legacy `AffectationService::affecterEnseignantPrincipal()` (jamais appelé en production).
- Elle appartient au module Scolarité (donnée dérivée de confort).
- `AffectationPedagogique` contient déjà l'information source canonique (`type = 'principal'`).
- *Conclusion :* Écriture directe de Scolarité par Pédagogie dans un service legacy, à supprimer à terme lors de la convergence.

## 11. Frontière RH
- Obtenue via le Contract `EnseignantsPedagogiquesReadContract` (injecté dans `OrganisationPedagogiqueContext`).
- Données RH consommées : `id`, `actif`, identité (`nom`), statut contractuel.
- `enseignant_id` représente l'ID de la table `enseignants` (qui référence `employes.id`), et non l'ID de la table `users`.

## 19. Architecture cible à proposer
- **SOURCE DE VÉRITÉ AFFECTATIONS :** `affectations_pedagogiques` (et `affectation_pedagogique_matieres` pour les spécialités).
- **SERVICE D'ÉCRITURE CANONIQUE :** `AffectationPedagogiqueService` via `AffectationPedagogiqueServiceInterface`.
- **SERVICE LEGACY :** `AffectationService` (à isoler, puis supprimer sans appel en production).
- **RESPONSABILITÉS PRINCIPAL / ASSISTANT / MATIÈRE :** Portées par la colonne `type` et validées par le service canonique selon le mode du cycle (`OrganisationCycle`).
- **LIEN AVEC OFFRE PÉDAGOGIQUE :** `offre_pedagogique_id` obligatoire pour les affectations de type `matiere` (secondaire), nullable pour `principal` / `assistant` (maternelle/primaire).
- **FRONTIÈRE RH :** Consommation exclusive via `EnseignantsPedagogiquesReadContract` (aucun import direct de `RH\Models`).
- **FRONTIÈRE SCOLARITÉ :** Consommation exclusive via `ClassesPedagogiquesReadContract` et `AcademicStructureCatalogContract` (aucun import direct de `Scolarite\Models`).
