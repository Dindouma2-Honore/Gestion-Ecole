# Pédagogie P1.2.1 — Correction binding Affectation

Bugfix architectural minimal. **Aucune refonte fonctionnelle des affectations.**
Une seule anomalie corrigée : double binding / implémentation résolue non conforme au Contract.

---

## 1. Cause exacte

`app/Modules/Pedagogie/PedagogieServiceProvider.php` enregistrait **deux bindings** pour la
**même interface** (`App\Modules\Pedalogie\Contracts\AffectationPedagogiqueServiceInterface`,
la 2ᵉ ligne répétant la FQCN de la 1ᵉʳ) :

```php
$this->app->bind(AffectationPedagogiqueServiceInterface::class, AffectationPedagogiqueService::class);   // ligne 45
$this->app->bind(MatiereServiceInterface::class, MatiereService::class);                                  // ligne 46
$this->app->bind(\App\Modules\Pedagogie\Contracts\AffectationPedagogiqueServiceInterface::class,
                 \App\Modules\Pedagogie\Services\AffectationService::class);                              // ligne 47 ← écrase la 45
```

En Laravel, le dernier `bind()` gagne → l'interface résolvait **`AffectationService`**.
Or `AffectationService` déclare `implements AffectationPedagogiqueServiceInterface`
**sans implémenter** `enregistrer()` ni `estAutorise()` → fatal PHP à l'autoload de la classe.
Consommateur Filament (`AffectationPedagogiqueResource::enregistrer()`) et tests qui résolvent
l'interface déclenchent donc le fatal.

Message relevé (baseline, 10/10 erreurs identiques) :

```
Fatal error: Class App\Modules\Pedagogie\Services\AffectationService contains 2 abstract
methods and must therefore be declared abstract or implement the remaining methods
(App\Modules\Pedagogie\Contracts\AffectationPedagogiqueServiceInterface::enregistrer,
 App\Modules\Pedagogie\Contracts\AffectationPedagogiqueServiceInterface::estAutorise)
in /var/www/html/app/Modules/Pedagogie/Services/AffectationService.php on line 13
```

Aucune des deux implémentations n'a été choisie « à l'aveugle » : détermination faite dans le code (§2–§3).

## 3. Contract

`AffectationPedagogiqueServiceInterface` exige exactement 2 méthodes.
`AffectationPedagogiqueService` les implémente **avec logique existante** (pas de méthode factice) :

- `enregistrer()` (l. 21–113) : validation, garde-fous contexte/année/mode, résolution de l'offre,
  règles de doublon, transaction + audit → retourne `AffectationPedagogique`.
- `estAutorise()` (l. 115–128) : enseignant actif + offre effective + affectation active couvrant la date,
  principal / matière / assistant (périmètre spécialisé).

`AffectationService` : **0 / 2** méthodes du Contract, et il n'existe aucune logique
`enregistrer`/`estAutorise` dans ce fichier → impossible de le rendre compatible sans invention.

## 4. Implémentation canonique retenue

**`App\Modules\Pedagogie\Services\AffectationPedagogiqueService`**

Justification (code uniquement) :

1. Seule classe qui implémente réellement les 2 méthodes du Contract, avec validation,
   transactions, `lockForUpdate` et audit — identique aux autres services du module.
2. Seul consommateur applicatif de l'interface en production :
   `AffectationPedalogiqueResource.php:105` appelle `->enregistrer($data, $record?->getKey())`
   → exige précisément la signature de `AffectationPedagogiqueService`.
3. `AffectationService` possède **0 consommateur direct** dans `app/` (hors son propre fichier et
   la ligne de binding supprimée) : il n'était relié au reste de l'application **que** par ce binding,
   donc gagner ne « nourrit » aucun consommateur.
4. Aucune logique métier n'a été déplacée ni fusionnée.

## 6. Correction du Contract chez `AffectationService`

`AffectationService` déclarait `implements AffectationPedagogiqueServiceInterface` sans pouvoir
le satisfaire : cette **déclaration falsifiée** a été retirée (avec son `import` devenu inutile).

- Le Service **n'est pas supprimé** (il reste disponible pour d'éventuels consommateurs directs),
  **non renommé**, **aucune méthode/logique modifiée** : seul le `implements` non satisfait disparaît.
- Sans cela, la classe restait **impossible à charger** (fatal « contains 2 abstract methods »)
  même après rétablissement du binding unique.
- Aucune méthode factice ajoutée à `AffectationPedagogiqueService` ni ailleurs.
