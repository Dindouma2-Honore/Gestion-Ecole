# F3.3 — Réparation permissions Spatie

## Statut
TERMINE

## Cause retenue
- **Fait prouvé** : Les migrations de création des permissions WhatsApp et Technique (`2026_09_13_160100_add_whatsapp_permissions.php`, `2026_09_13_170100_add_template_permissions.php`, `2026_09_13_160100_add_technical_permissions.php`) avaient été exécutées historiquement (marquées dans la table `migrations`), mais la table `permissions` de la base de données locale avait été recréée ou vidée ultérieurement sans qu'un mécanisme de seeder global ne réinsère ces permissions.
- **Hypothèse historique** : Les réinitialisations de base de données ou les tests exécutés de manière isolée nettoyaient ou créaient les tables de base sans rejouer les migrations spécifiques de modules de manière globale ou persistante sur l'environnement de développement.

## Solution implémentée
Création d'un seeder dédié et idempotent (`ActivePermissionsRepairSeeder`) enregistré dans `DatabaseSeeder.php`, utilisant `Permission::findOrCreate($permission, 'web')` pour garantir de manière idempotente la présence des 16 permissions requises par WhatsApp, les templates de communication et le module Technique.

## Source de vérité des permissions
- `App\Modules\Communication\Support\WhatsAppTemplatePermissions::ALL` pour les templates.
- Les tableaux explicites pour WhatsApp (`whatsapp.view`, `whatsapp.connect`, `whatsapp.send`, `whatsapp.simulate`) et Technique (`technique.view`).

## Attribution aux rôles
Aucune attribution automatique aux rôles n'a été ajoutée par ce seeder (séparation stricte entre existence de la permission et attribution aux rôles). Seul le rôle `Fondateur` conserve ses attributions existantes via `RolesAndPermissionsSeeder`.
