# F4.2 — Bridge Auth → Authorization V1

## Statut
TERMINE

## Architecture retenue

Flux :

```
Auth User
   ↓
Bridge (AuthenticatedAuthorizationService)
   ↓
AuthorizationContract (bind SocleServiceProvider)
   ↓
AuthorizationService (moteur pur, inchangé)
   ↓
USER + GROUP + RH_POSITION
   ↓
authorization_grants
```

## Contrat créé/réutilisé
- **Créé** : `App\Modules\Socle\Contracts\AuthenticatedAuthorizationContract` (canRead / canWrite / canExecute / canPrint sur `string $featureCode`).
- Aucun équivalent existant : `UserAuthorizationServiceContract` a été inspecté, il s'agit d'un service legacy basé sur les rôles (`hasRole`), pas d'un pont vers V1.

## Implémentation
- `App\Modules\Socle\Services\AuthenticatedAuthorizationService` :
  - injecte `AuthorizationContract` et `Illuminate\Contracts\Auth\Factory` ;
  - résout l'ID de l'utilisateur authentifié (`getAuthIdentifier()`) ;
  - délègue intégralement à `AuthorizationContract` ;
  - ne requête jamais `authorization_grants`, ne recalcule ni GROUP ni RH_POSITION, ne duplique pas `decide()`, n'écrit aucun grant ;
  - ne crée aucune dépendance AuthorizationService → Spatie, aucun SubjectType ROLE ajouté.

## Gestion guest
- Visiteur non authentifié (`guard()->user() === null`) => **DENY** : les 4 méthodes retournent `false`. Couvert par le test `test_guest_is_denied_on_every_action`.

## Gestion Fondateur
- **Comportement retenu** : comportement V1 strict (aucun bypass).
- **Justification** : inspection préalable effectuée — aucun mécanisme central `Gate::before` / `Gate::after` n'existe dans le dépôt (`app/`, providers). Conformément à la consigne, aucun `hasRole('Fondateur')` n'a été ajouté dans `AuthorizationService`, aucune seconde dépendance vers Spatie n'a été créée. Le besoin d'un bypass Fondateur est documenté (F4.1) pour un lot ultérieur.
- Test documenté : `test_fondateur_keeps_strict_v1_behaviour_without_central_bypass`.

## Bindings
- `SocleServiceProvider::register()` : `AuthenticatedAuthorizationContract` → `AuthenticatedAuthorizationService`, aux côtés du binding existant `AuthorizationContract` → `AuthorizationService`.
- Bind effectué uniquement dans le provider propriétaire du Socle (aucun binding Socle dans RH).
